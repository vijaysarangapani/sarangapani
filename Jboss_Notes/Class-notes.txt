JBOSS supports modular architecture

At the time of starting JBOSS server, it will read xml file. In that xml, based on the modules that are defined, server will go and check its module in the modules directory

Modules contains jar files, that jar file contains classes
Once that classes are loaded, its services will be started

Based on our application requirement, we can choose, what are the modules to be loaded. so that only that module services will be started.
We can reduce burden on the server, by loading only required classes (services)

-------------------------------------------------------

	module add --name=com.oracle --resources=F:\Softwares\Oracle\ojdbc6.jar --dependencies=javax.api,javax.transaction.api

2. Update the driver by executing a command
	/subsystem=datasources/jdbc-driver=oracle:add(driver-name=oracle,driver-module-name=com.oracle)

3. Create a Datasource
	data-source add --jndi-name=java:/Oracle_DS_PAYTM --name=Oracle_DS_PAYTM  --connection-url=jdbc:oracle:thin:@localhost:1521:xe --driver-name=oracle --user-name=system --password=admin

	/subsystem=datasources/data-source=Oracle_DS_PAYTM:test-connection-in-pool

Steps to configure JBOSS with Apache by using mod_jk 
---------------------------------------------------
1. Install Apache WebServer
2. We can install by executing a command
	./configure --prefix=/opt/Apache_2.4.25
	make
	make install
3. Make sure, we have mod_jk module in <apache-home>/modules directory (If it's not available download and place in modules dir)
4. Load mod_jk module by adding a parameter
LoadModule jk_module modules/mod_jk.so in httpd.conf file
5. Create 3 new files 
		mod-jk.conf
		uriworkermap.properties
		workers.properties 
	in <apache-home>/conf directory	
6. Include mod-jk.conf in httpd.conf file by adding a parameter 
Include conf/mod-jk.conf 
7. In mod-jk.conf file define the location of workers.properties, jk log file location, log level, log format, jkmount application context, Allow from IP Address, jkmount file - the location of uriworkermap.properties
8. In uriworkermap.properties map the context root of an application which we have to access
9. In workers.properties file, specify
		worker node port, ajp connector port number of the appserver instance, host name, protocol, lbfactor, load balancer workers, sticky session to true or false e.tc.
10. Start WebServer and access applications through WebServer
11. If a request is going through Webserver we can find the request info. in access log  file of apache in Apache/logs directory.

SSL (Secure Socket Layer)
-------------------------
It is to provide secure communication between client and server.

1. By using self signed certificates
2. By using signer certificates or CA certificates / Third party certificates



1. Create a keystore file 

keytool -genkey -alias aliasname -keyalg RSA -keysize 2048 -keystore abc.keystore -keypass keystorepassword -validity 365

2. Create a CSR by using a command

keytool -certreq -alias aliasname -keysize 2048 -file certreq.csr -keystore abc.keystore

send CSR to client asking for a certificate
Now we will receive three files
	1. root certificate
	2. intermediate certificate
	3. public certificate


3. keytool -importcert -alias test123 -file root1.cer -keystore abc.keystore -storepass admin123

4. keytool -import -alias verisigninter -file Intermediate.pem -keystore abc.keystore -trustcacerts

5. keytool -import -alias public -file public.pem -keystore abc.keystore -trustcacerts

 After importing certificates
4. Take a backup of standalone.xml/domain.xml (or full/ha/full-ha) and add https connector, https port number 8443, protocol, enabled=true, key-alias, key password and keystore file location in <subsystem xmlns="urn:jboss:domain:web:2.2"> and restart the server

5. We can list the certificates by using a command
keytool -list -keystore abc.keystore -v
